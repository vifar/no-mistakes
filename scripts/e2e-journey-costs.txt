# Measured cost of the end-to-end journeys, in seconds.
#
# The suite is split across shards, and the split balances by MEASURED TIME
# rather than by test count: a single journey can cost more than every other
# test in a shard together, so a count-based split leaves one shard as the
# suite's long pole and the rest idle.
#
# These numbers are the measured cost of each journey on the CI runner, taken
# from a full run of the bucket. A journey that is not listed costs its
# default below, which is small on purpose: an UNMEASURED journey is
# expected to be an ordinary one, and a missing entry must not let a journey
# dominate a shard.
#
# The placement is the LONGEST-PROCESSING-TIME-FIRST rule: the measured
# journeys go to the least loaded shard, one at a time, and the rest follow
# in the same order. The result is deterministic - the same measurements
# always produce the same split - and it is a function of the measurements
# alone, so a journey does not move when an unrelated one is added.
#
# A journey that is not measured costs default_journey_seconds. Raising a
# number here is a measurement, not a guess: the value is what the journey
# actually cost.
#
# The measured total of the journeys a shard carries is about 3350 seconds,
# and three shards carry that inside the 2400 second budget. The journeys
# the terminal worker owns are listed here too, so the file is a complete
# record of what the bucket costs; the placement leaves them out of the
# shards.
default_journey_seconds=15
